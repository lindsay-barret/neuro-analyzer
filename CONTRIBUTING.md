# Contributing to neuro-analyzer

Thank you for your interest in contributing. This is a small, focused project — contributions are welcome but please read this document first.

## Before you start

### Critical: no patient data, ever

This repository must never contain any patient-identifiable information. Before submitting a PR or issue with attached files, verify:

- No DICOM, NIfTI, or other medical imaging files (these are blocked by `.gitignore` but double-check)
- No file paths containing real names, dates of birth, or medical record numbers
- No screenshots or images of real medical scans
- No content of generated reports about real patients (even if you think they're "anonymized")

If you want to contribute an example or test case, use:
- Public datasets from [OpenNeuro](https://openneuro.org)
- Synthetic data generated by the test suite

### Scope of this project

`neuro-analyzer` is intentionally narrow. It is a **research and educational tool** for pediatric structural MRI re-analysis.

This project is actively maintained until **December 2027**, after
which the repository will be archived. Pull requests submitted after
that date will not be reviewed. See README for details on the
project lifecycle.

Out-of-scope contributions that will likely be declined:

- Features positioning the tool as clinical or diagnostic
- Removal or weakening of medical disclaimers
- Bundling of FreeSurfer or other non-redistributable software
- Features that compromise patient data protection
- Clinical validation claims (e.g. cohort studies, diagnostic accuracy assertions) without IRB-approved protocol and peer-reviewed publication
- Productization into a hosted SaaS, web service, or commercial offering
- DICOM listener, PACS integration, EHR/HIS integration, or any feature that turns the pipeline into an always-on networked service
- Real-time, streaming, or live-acquisition processing
- Authentication, user accounts, role-based access, or multi-tenant features
- Regulatory submission support (FDA 510(k), CE marking, COFEPRIS registration, IMDRF SaMD compliance work)

In-scope contributions warmly welcomed:

- Bug fixes
- Improved error handling, especially for malformed cortex edge cases
- Documentation improvements (especially translations to other languages)
- Additional public dataset examples
- Performance improvements
- Testing on additional malformations of cortical development beyond pachygyria
- Pediatric-specific atlas integration
- Improved FastSurfer error recovery

## How to contribute

### Reporting issues

Use the GitHub Issues tracker. For bug reports, please include:

1. Operating system and Python version
2. Whether running native or Docker
3. The exact command you ran (sanitized — no patient paths)
4. The error message or unexpected behavior
5. A minimal reproducible example using public/synthetic data if possible

### Submitting changes

1. Fork the repository
2. Create a feature branch: `git checkout -b feat/your-feature`
3. Make your changes with clear commit messages
4. Add or update tests in `tests/`
5. Install dev dependencies: `pip install -r requirements-dev.txt`
6. Install pre-commit hooks so secrets, large files, and identifying
   patterns are blocked before commit: `pre-commit install`
7. Run the full test suite locally: `pytest tests/`
8. Run the linter: `ruff check src/ tests/`
9. Run the secrets scan: `gitleaks detect --source .`
10. Open a Pull Request with a clear description of the change and its motivation

### Troubleshooting

#### Pre-commit fails with `SSL_CERTIFICATE_VERIFY_FAILED` on Windows

If you run pre-commit behind an antivirus that performs TLS inspection
(Avast, Kaspersky, ESET, BitDefender, etc.), some hooks may fail to
download because the antivirus's root certificate is either missing
from Python's default trust store or not RFC 5280 compliant (a known
issue with some auto-generated MITM roots whose `Basic Constraints`
extension is not marked critical, which OpenSSL strict mode rejects).

Workaround using [truststore](https://github.com/sethmlarson/truststore),
which delegates TLS validation to the OS native trust store:

1. Install `truststore` in your dev venv:

   ```bash
   pip install truststore
   ```

2. Create a `sitecustomize.py` inside your venv's site-packages
   directory (Windows: `.venv\Lib\site-packages\sitecustomize.py`;
   Linux/macOS: `.venv/lib/python3.X/site-packages/sitecustomize.py`)
   with the following content:

   ```python
   try:
       import truststore
       truststore.inject_into_ssl()
   except ImportError:
       pass
   ```

3. Run `pre-commit install` and `pre-commit run --all-files`.

You will need to repeat steps 1 and 2 if you recreate your venv. This
workaround is intentionally not bundled as a dev dependency because it
is only required in this specific environment.

#### Pre-commit hooks fail with "Access denied" on Windows

On Windows with active antivirus software (Defender, Avast, etc.),
pre-commit hook binaries cached under `~/.cache/pre-commit/` may be
quarantined. If `pre-commit run` fails with permission errors on hook
executables, add `%USERPROFILE%\.cache\pre-commit\` to your antivirus
exclusion list, or temporarily disable real-time protection during
pre-commit runs.

#### `pip install` fails with `RecursionError` after the truststore workaround is active

If you've applied the truststore injection above to bypass Avast's SSL inspection, you may then find that any subsequent `pip install` (including `pip install -r requirements-dev.txt` from step 5 of "Submitting changes") crashes with:

```
File ".venv\Lib\site-packages\pip\_vendor\truststore\_api.py", line 300, in verify_mode
    _original_super_SSLContext.verify_mode.__set__(self._ctx, value)
File "...\Lib\ssl.py", line 679, in verify_mode
    super(SSLContext, SSLContext).verify_mode.__set__(self, value)
  [Previous line repeated 959 more times]
RecursionError: maximum recursion depth exceeded
```

**Cause.** Recent pip releases (25.x) vendor their own copy of `truststore` under `pip._vendor.truststore`. When `sitecustomize.py` injects the user-installed `truststore` at interpreter startup, it patches `ssl.SSLContext.verify_mode`. Pip's vendored truststore then tries to call what it believes is the *original* descriptor setter — but that "original" is now the patched one, which calls itself. Two truststore implementations stacked on the same `SSLContext` class collide.

Reproducible on Windows + Python 3.13 (Microsoft Store distribution) + pip 25.x. Not specific to Avast — any environment that injects `truststore` via `sitecustomize.py` and then runs a modern pip will hit it.

**Workaround — preferred.** Avoid `pip install` for development tools. `pre-commit` installs its hooks (ruff, gitleaks, etc.) into its own isolated environments under `~/.cache/pre-commit/`, bypassing this venv's pip entirely:

```bash
pre-commit run --all-files          # run every configured hook
pre-commit run ruff --all-files     # run only ruff
pre-commit clean && pre-commit install --install-hooks  # regenerate hook envs
```

`pytest` does not touch SSL and runs normally.

**Workaround — escape hatch.** If a direct `pip install` is genuinely needed (e.g., to add a runtime dependency), temporarily move `sitecustomize.py` aside for the duration of the install:

```powershell
# Windows PowerShell
Move-Item .venv\Lib\site-packages\sitecustomize.py $env:TEMP\sitecustomize.py.bak
pip install <package>
Move-Item $env:TEMP\sitecustomize.py.bak .venv\Lib\site-packages\sitecustomize.py
```

Reinstate `sitecustomize.py` immediately after — without it, subsequent SSL-using scripts (notably the Anthropic API client used by the visual analysis step) lose their TLS bypass.

### Code style

- Follow PEP 8, enforced by `ruff`
- Type hints encouraged for new code
- Docstrings for public functions (NumPy or Google style)
- Comments in English (the README is bilingual ES/EN, but code stays in English for international readability)

### Commit messages

Use conventional commit format when possible:
- `feat: add support for X`
- `fix: handle empty NIfTI in pipeline`
- `docs: clarify FreeSurfer optional install`
- `test: add synthetic data smoke test`
- `refactor: extract reporting module`
- `chore: bump dependencies`
